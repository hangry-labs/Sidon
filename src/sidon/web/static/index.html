What to expect

Restoration resynthesizes speech and may change the voice or introduce artifacts. Compare with the original. Speaker separation always returns two mono tracks; these are relative speaker labels, not identified people. Long silences and ambiguous overlaps can cause speaker swaps.

Audio jobs, ready for your workflow

Use versioned audio endpoints for direct files or asynchronous jobs. The Studio job API remains supported. No streaming is implemented.

1. Submit audio

curl -X POST http://localhost:7868/api/jobs \
  -F file=@voice.wav \
  -F mode=enhance \
  -F strength=1 \
  -F output_format=wav

Modes: enhance, separate, separate_enhance, convert. Output formats: wav, flac, opus, mp3, m4a, aac, ogg. Returns HTTP 202 with a job ID.

2. Poll and download

curl http://localhost:7868/api/jobs/JOB_ID

curl -OJ http://localhost:7868/api/jobs/JOB_ID/files/results.zip

curl -X DELETE http://localhost:7868/api/jobs/JOB_ID

Wait for status: done. Track filenames are listed in outputs. Downloads include a processing manifest.

Public audio API

POST /v1/audio/enhancements · POST /v1/audio/separations · POST /v1/audio/conversions

Send multipart file, optional model and response_format. The default response is an audio file (ZIP for two tracks). Use response_mode=job for HTTP 202. These are native audio extensions with OpenAI-style conventions.

curl -X POST http://localhost:7868/v1/audio/enhancements -F file=@voice.wav -F response_format=opus --output restored.opus

GET /v1/models · GET /v1/audio/queue · GET /v1/audio/jobs/JOB_ID · POST /v1/audio/jobs/JOB_ID/cancel

One shared FIFO worker. Capacity rejection returns HTTP 429 with Retry-After. Running cancellation waits for a safe processing boundary.

Service endpoints

GET /healthz · GET /api/status · GET /api/jobs · PUT /api/settings · POST /api/models/{enhance|separate} · GET /api/gpu

Model actions accept {"action":"load"} or {"action":"unload"}. These routes use the same authentication as jobs.

OpenAPI schema

If an API key is configured, send Authorization: Bearer YOUR_KEY. All clients of one instance share its jobs. Use separate instances for separate trust boundaries.
